# Bài tập 5: Thiết kế API quản lý thư viện

## 1. Thiết kế các endpoint

### 1. Lấy danh sách tất cả sách

| Thuộc tính  | Giá trị                                                  |
|-------------|----------------------------------------------------------|
| HTTP Method | GET                                                      |
| URL         | `/books`                                                 |
| Thành công  | `200 OK`                                                 |
| Lỗi 1       | `500 Internal Server Error` – lỗi hệ thống hoặc database |
| Lỗi 2       | `503 Service Unavailable` – server đang bảo trì          |

---

### 2. Lấy chi tiết sách theo id

| Thuộc tính  | Giá trị                               |
|-------------|---------------------------------------|
| HTTP Method | GET                                   |
| URL         | `/books/{id}`                         |
| Thành công  | `200 OK`                              |
| Lỗi 1       | `404 Not Found` – không tìm thấy sách |
| Lỗi 2       | `400 Bad Request` – id không hợp lệ   |

Ví dụ:

```http
GET /books/1
```

---

### 3. Thêm sách mới

| Thuộc tính  | Giá trị                                    |
|-------------|--------------------------------------------|
| HTTP Method | POST                                       |
| URL         | `/books`                                   |
| Thành công  | `201 Created`                              |
| Lỗi 1       | `400 Bad Request` – thiếu dữ liệu bắt buộc |
| Lỗi 2       | `409 Conflict` – sách đã tồn tại           |

---

### 4. Cập nhật toàn bộ thông tin sách theo id

| Thuộc tính  | Giá trị                                  |
|-------------|------------------------------------------|
| HTTP Method | PUT                                      |
| URL         | `/books/{id}`                            |
| Thành công  | `200 OK`                                 |
| Lỗi 1       | `404 Not Found` – không tìm thấy sách    |
| Lỗi 2       | `400 Bad Request` – dữ liệu không hợp lệ |

---

### 5. Xóa sách theo id

| Thuộc tính  | Giá trị                              |
|-------------|--------------------------------------|
| HTTP Method | DELETE                               |
| URL         | `/books/{id}`                        |
| Thành công  | `204 No Content`                     |
| Lỗi 1       | `404 Not Found` – không tồn tại sách |
| Lỗi 2       | `403 Forbidden` – không đủ quyền xóa |

---

### 6. Tìm sách theo tác giả

| Thuộc tính  | Giá trị                                    |
|-------------|--------------------------------------------|
| HTTP Method | GET                                        |
| URL         | `/books?author={author}`                   |
| Thành công  | `200 OK`                                   |
| Lỗi 1       | `400 Bad Request` – query parameter sai    |
| Lỗi 2       | `500 Internal Server Error` – lỗi hệ thống |

Ví dụ:

```http
GET /books?author=Nguyen Van A
```

---

## 2. Ví dụ Request/Response

### a) Thêm sách mới thành công

**Request**

```http
POST /books
Content-Type: application/json
```

Body:

```json
{
    "title":"Lap trinh Java",
    "author":"Nguyen Van A",
    "year":2024,
    "available":true
}
```

**Response**

Status:

```http
201 Created
```

Body:

```json
{
    "id":1,
    "title":"Lap trinh Java",
    "author":"Nguyen Van A",
    "year":2024,
    "available":true
}
```

---

### b) Tìm sách theo tác giả không có kết quả

**Request**

```http
GET /books?author=Tran Van X
```

**Response**

Status:

```http
200 OK
```

Body:

```json
[]
```

Giải thích: Request hợp lệ nhưng không có dữ liệu phù hợp nên trả về mảng rỗng.

## 4. Câu hỏi lý thuyết

### Sự khác nhau giữa PUT và PATCH

#### PUT

- Dùng để cập nhật toàn bộ tài nguyên.
- Client phải gửi đầy đủ dữ liệu.
- Nếu thiếu trường thì dữ liệu cũ có thể bị ghi đè.

Ví dụ:

```json
{
    "title":"Java",
    "author":"Nguyen Van A",
    "year":2024,
    "available":true
}
```

#### PATCH

- Dùng để cập nhật một phần tài nguyên.
- Chỉ gửi các trường cần thay đổi.

Ví dụ:

```json
{
    "available":false
}
```

### Trong bài tập cập nhật sách nên dùng PUT hay PATCH?

Nên dùng **PUT** vì yêu cầu bài tập là **cập nhật toàn bộ thông tin sách theo id**.

PUT phù hợp vì nó thay thế toàn bộ dữ liệu của sách. Nếu chỉ sửa một vài thuộc tính như `title` hoặc `available` thì nên sử dụng PATCH.
